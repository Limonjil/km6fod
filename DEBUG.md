## Правки по итогам (все применены без перезагрузки)

- F8 → `post-fs-data.sh`: `chmod 0755 files/trantp_probe` (Magisk теряет права при установке).
- F9 → переарм жеста на `DisplayState::LOCKSCREEN` (AOD на устройстве не приходит никогда), включение через `trantp_probe 2 3 fp1`.
- F12 → `posix_spawn` + поток с `waitpid` вместо `fork()`.
- F10 → `hbm: off` не пишет узел и не верифицирует, если подсветка уже 0 (драйвер такие записи отбрасывает).
- F11 → на `finger up` свет не гасится, если `frame_good_` установлен: ждём результат движка, окно закрывает сторож.

Прогноз для F11: при снятом кадре в логе `finger up with a captured frame, light kept for the result`, затем `onAcquired` и `authentication succeeded` при горящей панели.

## F21 — режим «держать дисплей интерактивным» (hold mode)

Реализован (`src/hold_mode.cpp`): wakelock `km6fod_dark` + подсветка 0 + повторное
зажигание через движок раз в 15 с. **Отключён**: вход был привязан к переходу
`DisplayState → LOCKSCREEN`, а это событие приходит и когда экран **будится** на
локскрин — режим гасил панель прямо перед глазами (измерено: `hold: entered` сразу
за `input keyevent 224`, затем чёрный экран).

Что нужно для корректного включения: настоящий триггер «экран погас» (сейчас его
нет ни в `DisplayState`, ни в AIDL), либо порог по подсветке с гистерезисом.
Код оставлен, вызов закомментирован в `session.cpp`, восстановление яркости
работает (`holdModeRecover` при старте HAL, в `uninstall.sh`, таймаут 30 мин).

## F22 — параллельная сборка нестабильна

`build.sh` при `nproc=16` периодически падал с `no such file or directory` на
случайных файлах (гонка `.cmd`-обёрток NDK при 16 параллельных вызовах). При
`max_jobs=2` сборка проходит стабильно. Проверять сборку после `--clean` при
изменениях в `build.sh`.

## F23 — режим удержания удалён

`hold_mode` писал яркость в узел подсветки в обход фреймворка и разъезжался с ним:
после разблокировки подсветка оставалась гореть, а на локскрине могла не зажечься.
Симптом воспроизведён и вылечен: яркость снова применяет фреймворк
(`settings put system screen_brightness` → узел меняется: 45 → 723, 120 → 1927).
Режим удалён целиком (`src/hold_mode.*`, вызовы, блок в `uninstall.sh`), вместе с
uinput-инжектором, держателем жеста и `wake_helper.sh`. Осталось: один процесс
`fp_hal`, один Magisk-модуль.

## F24 — попытка №2 режима удержания: механизм есть, автомат нестабилен

Правильная схема (яркость через фреймворк, а не через узел) подтверждена:
`settings put system screen_brightness 0` из фонового контекста Magisk работает
(rc=0, узел становится 0). Помощник `hold.sh` берёт wakelock, растягивает
`screen_off_timeout`, гасит подсветку и возвращает всё назад.

Проблема: автомат входа/выхода осциллирует — вход по условию «bl==0 и настройка>0»
и выход по файлу `hold_off` (создаётся HAL на любое касание вне зоны сенсора)
срабатывают в одном цикле, режим входит и сразу выходит. Нужен явный конечный
автомат с приоритетами и журналом каждого решения, а не два независимых условия.

Старт помощника из `service.sh` **отключён**, файл оставлен.

## Открытый симптом

«Первый раз срабатывает, дальше нет»: после успешной разблокировки следующее
прикладывание пальца к погашенному экрану не даёт ничего — в логе HAL **нет даже
строки `session: touch`** и нет `FOD wake gesture`.
