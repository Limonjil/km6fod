## Что уже доказано — не переоткрывать

- `echo 0 > /sys/class/leds/lcd-backlight/brightness` при **включённом** экране обратим
  (723 → 0 → 300 → 723); при спящем дисплее запись игнорируется.
- `cmd display set-brightness 0` фреймворк зажимает до bl=16 (минимум).
- Драйвер панели отказывает в HBM, когда дисплей не интерактивен:
  `display state is slept or idle, skip set hbm node`.
- Контроллер тача уходит в `TRAN_GESTURE_SUSPEND_MODE` через ~1 с после гашения
  (`dmesg | grep tran_touch`), MT-событий в этом режиме нет.
- Жест: `fts_gesture_readdata: gesture_id=36` → `GestureIdTranslate: g_gtp_gesture=0xcc` →
  `GestureHandle: Sorry, this gesture has been disabled`.
- `/proc/gesture_function`: `echo fp1` → `code1[be] enable[1]`; `echo cc1` → `code1[cc] enable[1]`
  (событие в userspace не пришло). Вендорский путь ITrantp `(2,3,"fp1")` пишет не тот узел
  (`/proc/nvt_selftest` → `Invalid value! count = 3`).
- AOD/doze на этом GSI не работают: DozeService стартует, но экран остаётся `mState=OFF`.
- Инъекция `KEYCODE_WAKEUP` из shell/HAL работает, но в модуль возвращать её не нужно.

## Правила работы

- Наблюдение / гипотеза / доказанная причина — маркировать явно. Одна переменная за
  эксперимент, предсказание до запуска. Ребут — только с разрешения владельца.
- Никаких «невозможно» без проверки интерфейса и названного отрицательного теста
  (`cmd -l`, `cmd display help`, `dumpsys display`, `settings list`, sysfs-узлы, strings
  драйвера).
- Первая фаза — только чтение: `dmesg`, sysfs, `dumpsys`, `strings adaptive-ts.ko`,
  дизассемблер модуля (NDK в `/c/Users/Limonjil/Desktop/android/android-ndk-r26d`).
  Никаких записей в узлы на этой фазе.
- Сначала разобрать `adaptive-ts.ko` и панельный драйвер статически, потом один
  контролируемый тест на устройстве.
- Веди `PANEL-RE-LEDGER.md` (гипотеза, тест, результат, вердикт — по строке).
- Итог — `PANEL-RE-FINDINGS.md` по-русски: ответы на 5 вопросов, доказательства, и либо
